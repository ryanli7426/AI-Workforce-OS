# AI Workforce OS
## PRODUCT_UX_SPEC — 完整产品界面与交互规格

- **版本：** 1.0
- **文档类型：** Product UX Specification
- **适用产品：** AI Workforce OS
- **设计目标：** 将 AI 员工组织、工作、沟通和运营整合为一个可操作的管理平台。

---

# 1. 设计方向

## 1.1 产品体验定位

产品应像一个成熟的企业级工作平台，而不是开发者工具或纯技术监控面板。

设计参考方向：
- Linear：清晰的信息层级、任务管理和快捷操作。
- Vercel：简洁、克制的视觉语言。
- 现代企业 SaaS：完整的权限、组织、运营和管理体验。

## 1.2 视觉原则

- 默认深色模式，同时支持浅色模式。
- 左侧主导航 + 顶部全局工具栏 + 主内容区。
- 信息密度适中，避免过度装饰。
- 状态、风险和待处理事项清晰可见。
- 统一使用卡片、表格、筛选器、详情面板和时间线。
- 所有核心操作必须有明确反馈。
- 桌面端体验完整，移动端支持关键操作。

## 1.3 交互原则

1. 以用户任务为中心，而不是以技术模块为中心。
2. 重要信息优先展示，次要信息渐进披露。
3. 列表页负责浏览和批量操作，详情页负责完整上下文。
4. 任务、Agent、执行、工作流和消息之间可以相互跳转。
5. 高风险操作必须显示影响范围并要求确认或审批。
6. 所有异步操作都应显示当前状态。
7. 所有页面都必须设计加载、空状态、错误和无权限状态。

# 3. 页面规格

# 3.1 Overview — 指挥中心

## 页面目标
让管理者快速了解整个 AI 组织正在做什么、哪些事项需要关注、工作是否正常推进。

## 页面布局

### 顶部欢迎区
- 当前工作区名称。
- 日期和时间范围。
- 快速创建任务入口。
- 快速指令入口。

### 核心指标卡片
- 当前活跃任务。
- 今日完成任务。
- 在线 Agent。
- 待审批事项。
- 失败或阻塞任务。

### 当前工作区
显示正在执行的任务：
- 任务标题。
- 当前负责人。
- 执行 Agent。
- 所属项目。
- 执行进度。
- 当前状态。
- 最近更新时间。

### 需要关注
展示：
- 等待审批。
- 已阻塞任务。
- 执行失败。
- Agent 离线。
- 集成连接异常。

### 团队动态
按时间倒序展示任务创建、分配、开始执行、完成、失败和审批事件。

## 页面操作
- 创建任务。
- 查看任务详情。
- 进入 Agent 详情。
- 处理审批。
- 查看异常。
- 筛选时间范围。

# 5. 状态与反馈规范

所有异步对象必须有清晰状态。

## Task
Inbox、Pending、Planned、Assigned、Running、Blocked、Waiting Approval、Completed、Failed、Cancelled。

## Agent
Online、Busy、Idle、Degraded、Offline、Disabled。

## Runtime
Connected、Disconnected、Healthy、Degraded、Unavailable。

## Workflow
Draft、Active、Paused、Running、Completed、Failed、Archived。

## Approval
Pending、Approved、Rejected、Changes Requested、Expired、Cancelled。

状态颜色必须一致，且不能只依赖颜色，还要配合文字和图标。

---

# 6. 响应式与可访问性

- 桌面端是完整管理体验的主要目标。
- 平板端支持主要列表、详情和审批操作。
- 手机端支持通知、任务查看、会话和审批等关键操作。
- 所有关键操作支持键盘导航。
- 表单具有明确标签和校验提示。
- 状态不能只用颜色表达。
- 图表应提供可读的标题、单位和数据说明。

---

# 7. UX 验收标准

1. 每个一级导航都有完整页面。
2. 核心页面具备列表、详情和真实操作。
3. 每个页面有加载、空、错误和无权限状态。
4. 重要操作有确认和结果反馈。
5. 任务、Agent、执行、工作流、消息之间可以相互关联跳转。
6. Agent 状态和任务状态能够及时更新。
7. IM 会话能够关联任务。
8. 工作流能够查看节点执行进度。
9. 深色和浅色主题均可使用。
10. 桌面端完整可用，移动端关键操作可用。

**最终验收原则：这必须是一个真实可操作的 AI 员工组织管理平台，而不是一组静态 Dashboard 或展示型原型。**
