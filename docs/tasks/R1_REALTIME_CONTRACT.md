## Shared semantics

Notifications invalidate cached queries; HTTP queries remain authoritative. No streamed Task mutation, no synthetic DONE, no execution launch by subscribers. Dedicated journal, not the domain audit log. Existing Runner/controller and CLI may write through separate processes; an HTTP-only in-memory emitter is insufficient.

Parent provides `src/events/change-feed.ts` types and `web/src/realtime-model.ts` types; do not edit them. Notices contain only entity/resourceId/ticketId?/canonical ISO at. No payload text, commands, paths, reasons, logs, credentials or model results. Scope is always authenticated Owner+workspace; Project business owner is not access control.

Wire: GET /api/v1/events with Bearer and optional single `Last-Event-ID` header. No query parameters. A frame uses UTF8 text/event-stream: `event: change`, `id: CURSOR`, `data: JSON(ChangeNotice)` followed by blank line. Reset uses event reset, id cursor, data {reason:'initial'|'expired'|'replaced'|'future'}. Ready uses event ready, id cursor, data {}. Heartbeat is a comment, no ID. Cursor is opaque bounded ASCII, no credential; invalid syntax400, valid but wrong epoch/scope/pruned/future produces reset at current head. Missing cursor resets initial, then ready; resumable cursor replays ordered changes and gets ready after the initial backlog. Never advance a browser cursor before its onEvent succeeds. No total stream output cap, but frames/buffers/read inactivity/backpressure are bounded.

## Parent review refinement

- Query invalidation acceptance and network query completion are separate. React onEvent may acknowledge safe insertion into its bounded in-memory50ms invalidation batch; it does not assert the subsequent HTTP refetch succeeded. The stream cursor lives only inside that same connection run. Unmount/logout discards cursor and queued work together; a new run without a cursor receives initial reset and cancels/refetches active queries. Network query failures stay query errors plus polling recovery. Preserve batching; do not make N rapid DB saves force N full refetches. Pure browser client still awaits arbitrary onEvent and must retain its old cursor on handler rejection.
- Caller-owned promises cannot be forcibly cancelled. Race handler awaiting against abort, never advance after abort; React generation guards suppress subsequent stale effects. Cleanup guarantees internal reads/timers/listeners, not cancellation of external callback code.
- Send ready after draining the initial bounded backlog (including any reset); live means initial replay has caught up. HEAD for /events must be disabled/finite. Align preClose cleanup with CLI1.5s force-close window; abort drains and destroy remaining owned responses promptly.
- Existing API connectionTimeout10000ms can race a10000ms heartbeat. Set an appropriate stream socket timeout or heartbeat relationship and restore connection behavior on cleanup; test a live stream across the ordinary timeout window.
- Execution notices also refresh task-logs and logs query keys. Task/Project notices refresh dependent Task/execution/verification/log views. Supported R1 commands keep mandate/workspace ownership immutable; storage old/new audience tests do not claim a public reassignment API or end-to-end multi-user revocation policy.
- Journal notifications follow durable DB facts; Runner stdout-only appends do not mutate DB. Existing log polling remains, and this milestone must describe status notifications rather than claim continuous log output streaming.
