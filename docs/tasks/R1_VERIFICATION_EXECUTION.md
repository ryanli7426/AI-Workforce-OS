## Architecture refinement

Reuse existing generic detached RunnerClient/worker **as process supervisor**, under a separate `verification-runners` root, to launch one `node dist/verification/worker.js --input PATH` per VerificationJob. Its protocol IDs may use verificationId as executionId/assignmentId; this is a process protocol, NOT an Assignment/ExecutionRepository row. No fake Task execution DB records. The verification child performs checks using LocalVerifier supervised mode. Generic Runner already supplies authenticated stop, sequence/heartbeat, logging and process-group proof for the wrapper. Wrapper checks may themselves own detached groups; therefore wrapper terminal status alone never proves checks stopped. Only a validated signed verifier result with terminalConfirmed plus generic Runner terminal proof can authorize job completion/release. Lost wrapper/no report stays UNKNOWN, including SIGKILL; never replay checks.

A cancelled wrapper should handle SIGTERM/SIGINT, abort active checks, wait for group+exit+stream proof and durably persist cancellation result before exiting. Generic Runner graceMs 8000 is longer than verifier check shutdown bounds. Direct legacy LocalVerifier.verify remains available and existing tests must stay green. Shared pure parser/hash in src/verification/request.ts is provided by parent (parseVerificationRequest, parseVerificationPlan, verificationCanonicalJson, verificationRequestSha256); only type imports for model from copied actual sibling.
